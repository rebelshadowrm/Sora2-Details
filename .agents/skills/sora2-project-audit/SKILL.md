# Audit the project and repair supported defects

Read [the audit protocol](../../../docs/AUDIT-AND-CAPTURE-READINESS.md), [problem solving](../../../docs/PROBLEM-SOLVING-PROTOCOL.md), and [the research workflow](../../../docs/RESEARCH-WORKFLOW.md). Use build/test for repairs and validation, effect-lookup for semantics, and publish when the user authorizes release.

Inventory source revision/dirty changes, installed shortcut/version, running app/profile/helper PIDs, raw traces and saved encounters. Keep source, packaged, installed, simulated desktop and actual game results distinct. Verify the failing path before calling a defect resolved.

Check evidence quality as well as code: hashes, inline bytes, exact unique rows, caller scope, gaps, raw preservation and displayed provenance. Cross-capture pointer equality is insufficient. Back up derived records before enrichment changes; keep raw data immutable and preserve every unknown event.

Run explicit standalone lifecycle/bridge checks plus focused action-stream tests, Core and actual WPF replay/shutdown harnesses. Reconcile completed research ledgers against their raw source and timeline order. History inventory warnings about unavailable old traces must remain visible. Do not equate partial research coverage with verified meter totals or complete gameplay capture.

Repair reproducible defects and finish offline work autonomously. If live evidence is still necessary, prepare one minimal contrast and state what it will prove after all independent work is done. Player batches follow manual-stop cleanup without cutoff/keyword/extra approval.

For release readiness, audit packaging dependencies and user-visible claims, then carry an authorized publication through workflow/release/feed verification. Report passed checks, remaining limits and concrete next evidence. A completed audit is not complete event coverage.
