## What the player needs to do

For normal play, launch Sora 2 Details once. It requests approval during startup and then remains as the elevated tray owner. If the game is already running, capture starts after approval. If the game starts later, the app shows **Trails detected — Start capture?** and waits for the player's click; it does not show a UAC prompt or automatically attach at that point. CaptureHost, Python, and the bridge inherit the existing token. A separate research-only command wrapper must be run inside an already-elevated PowerShell session. The helper is time-limited, checks the game's exact EXE hash, and closes its game handle between fixed probe requests.

When the game exits, the app waits for clean debugger detach, breakpoint cleanup, and capture-helper exit, then hides the live meter and returns to its waiting tray state. Starting the game again while Sora 2 Details remains resident offers Start for its new PID. Close/minimize only hides the meter; choose **Exit Sora 2 Details** in the tray for full shutdown. The agent should report when a planned research session is armed and when it has stopped.

The player should not need to enter commands. A controlled battle with a visible command menu and one or two known moves is more useful than repeated prompts or many unannotated fights. Canceling the startup approval closes the app before capture; it is not a negative result about game data.
