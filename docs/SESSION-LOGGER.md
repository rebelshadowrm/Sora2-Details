# Long-running command-battle research logger

For normal play, launch `Start-Sora2Details.ps1` with `-Hours 2` through `-Hours 12`. Before the app opens, a short note explains that battle-data permission is needed, then Windows asks for approval. If the supported English `sora_2nd.exe` is already running, capture starts after approval. If not, the app waits in the system tray and asks before starting capture when Trails starts later. CaptureHost, the Python service, and the bridge inherit the approved app token; none invokes RunAs. The probe watches `BattleInit`, `BattleEnd`, the attributed attack-effect call, and the HP setter. It excludes effects observed outside the command-battle interval. Choose **Stop capture** in the tray to stop early; the probe restores its hardware breakpoints, detaches, and the app waits in the tray. Game exit performs the same capture cleanup. The session also ends when the configured duration (at most 12 hours) or hit limit is reached; Sora 2 Details remains resident and another session can be started from the tray.

The launcher prints a raw JSONL trace path under `%LOCALAPPDATA%/Sora2 Details/live/` and writes it to `live/current.json` there. The bridge writes one durable encounter JSON per observed fight under `%LOCALAPPDATA%/Sora2 Details/encounters/`; the desktop meter watches that folder. Raw attack observations include source/target pointers and IDs, candidate resolved amount and result flags, a bounded result frame, source/target context/status bytes, and first-seen identity snapshots. HP setter records preserve the observed before/max/requested values. Those raw records remain available after app updates. Older traces from before the installer release remain under the checkout's `.research-deps/live/`. Back up `%LOCALAPPDATA%/Sora2 Details/` before reinstalling Windows.

To rebuild projections after a bridge interruption, wait until the trace ends with `detached` or `target_exited`, then run:

```powershell
& C:\Python313\python.exe tools\live_capture_bridge.py "$env:LOCALAPPDATA\Sora2 Details\live\probe-session-REQUEST_ID.jsonl" --table-pac 'C:\Games\Trails in the Sky 2nd Chapter\pac\steam\table_en.pac'
```

Replace `REQUEST_ID` with the trace filename printed by the launcher. Each BattleInit in a trace now gets a stable encounter ID based on the trace name and ordinal, so rebuilding updates those encounter files instead of adding duplicates. The raw trace is the primary research record; the encounter JSON is a partial projection.

**Coverage limit:** this is not yet a complete combat log. It records the verified HP/result path and unmatched HP changes, but move IDs, support actions, misses, status-only effects, some result paths, true battle outcome, and automatic critical status remain unknown. The meter labels these encounters `PARTIAL`. Damage classes are recognized only for two exact, player-validated result flag values. Never treat a large hit or the `btlcom.AttackCritical` script callback as a confirmed per-hit crit. The long session captures bounded frame/context bytes on each hit so future comparisons can use rare, player-confirmed crits without short timed probes.

The launcher supports only the exact hash-gated game executable and validated English tables. Each capture is limited to 12 hours and 2,000,000 watched hits; if play continues after a bound, choose Start again from the tray. A clean detach during an open fight marks that encounter interrupted. When the game exits, the resident app waits for cleanup and clears the prior PID/session record. If the game starts again while the app is resident, a tray notification offers Start for the new PID. It does not capture play that happens before the new session arms.
